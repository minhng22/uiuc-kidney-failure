3. Experiment run step (ORIGINAL ATTEMPT) — STOPPED, root cause found
-----------------------------------------------------------------------------
UPDATE 2026-08-22 01:45 CDT: killed PID 2686002 (`kill -TERM -2686002`, its
process group) after ~1h44m of unexplained 98%+ CPU with no progress lines.
Root cause found via /proc/<pid>/fd inspection: cox.py's `if __name__ ==
"__main__":` block (pre-existing Stage 1b code) runs
CKD_FIFTY_FEATURES_HETEROGENEOUS FIRST, before FOUR_FEATURES/EIGHT_FEATURES/
TWENTY_FEATURES_HETEROGENEOUS. Since this build deliberately skipped
building rep99 data for that scenario (its rep1 source is mid a schema
migration by another session — see Data build step above),
`get_train_test_data(CKD_FIFTY_FEATURES_HETEROGENEOUS)` found no rep99 file
and fell through to `get_time_series_data_ckd_patients(scenario)` — a full
raw extraction from scratch, confirmed by fd 3 pointing at
`data/mimic-iv-2.2/hosp/labevents.csv` (13.7GB) at kill time. This is:
  (a) not part of Stage 2's scope (only FOUR_FEATURES/EIGHT_FEATURES/
      TWENTY_FEATURES_HETEROGENEOUS + kfre are Stage 2 targets),
  (b) touching machinery for a scenario explicitly flagged as another
      session's in-progress work, and
  (c) expensive/unbounded — the equivalent full-population extraction took
      ~2 hours for the rep1 pilot (see Background processes in
      EXPERIMENT_STATUS.md history).

No partial/corrupt files were left behind — killed before any CSV write
(extraction was still mid-read on labevents.csv, verified by listing
generated_data/rep99/ post-kill: no ckd_fifty_features_heterogeneous_*
files present).

Same root cause almost certainly affects dynamic_deephit.py,
hazard_transformer.py, logistic_hazard.py, rnnsurv.py's `__main__` blocks
too (Stage 1b added the 3 new scenarios to each following "the existing
pattern" of an already-hardcoded CKD_FIFTY_FEATURES_HETEROGENEOUS call) —
running `run_rep.sh 99` as originally planned would hit the same issue on
every remaining experiment.

**Fix under consideration** (not yet applied — asking user first since it
deviates from the approved plan's "reuse run_rep.sh as-is, no new script"):
instead of `python -m pkgs.experiments.<name>` (which executes each file's
full `__main__`), invoke each module's `run_*_model(scenario)` /
`run_kfre_model(scenario)` function directly per scenario, scoped to just
FOUR_FEATURES/EIGHT_FEATURES/TWENTY_FEATURES_HETEROGENEOUS (+ kfre limited
to FOUR_FEATURES/EIGHT_FEATURES) — mirroring the exact scoping pattern
already used for the 1c-0/1c pilot and rep2-5 extractions (`python -c
"..."` calling functions directly instead of running a script's `__main__`
that also touches CKD_FIFTY_FEATURES_HETEROGENEOUS). Requires no edits to
any previous-stage file — only a differently-scoped invocation.
