1. WHAT CHANGED
================================================================================

Gap 5a — patient-level censoring reference.
  The IPCW censoring reference that the integrated Brier score and the time-dependent AUC
  both weight by was built with
      Surv.from_dataframe(event='has_esrd', time='duration_in_days', data=df_train)
  on the RAW exported training frame, which is one row per lab EVENT. Every intermediate
  visit of a patient still under follow-up therefore entered the reference as its own
  TERMINAL censored observation. Measured on rep99:

      scenario                       rows    patients   row event rate   patient event rate
      four_features (train)          5806         500           0.0575               0.5000
      four_features (test)           3667         345           0.0938               0.7246
      eight_features (train)         1856         400           0.1907               0.6250
      eight_features (test)          1100         243           0.2800               0.8724
      twenty_features (train)        4575          20           0.0522               0.5000
      twenty_features (test)         9115          20           0.0325               0.5000

  Replaced by one terminal outcome per patient (pkgs/data_analysis/patient_outcomes.py:
  patient_level_outcomes). The construction was verified, not assumed — for all six
  frames verify_patient_outcomes() reported no problems: no duplicate subject_id, each
  patient's last row IS their maximum-duration row, and each patient's terminal event flag
  equals their maximum event flag (i.e. the exported frames really are truncated at the
  event, as time_series_store.process_patient_esrd intends). The terminal frame was also
  checked to be identical, row for row, to get_last_observation_data()'s output — the frame
  every model is actually scored on.

  Model-side alignment is now checked per model before its predictions are used
  (align_predictions_to_patients). Two real mismatches were found and are now handled
  rather than silently carried:
    - Dynamic-DeepHit and Hazard Transformer floor every duration to a whole day (both
      discretize time into day bins): 274 of four_features' 345 test patients, max
      difference 0.9986 d.
    - Weibull AFT replaces a duration of exactly 0 with 1e-5 (lifelines errors on a zero
      duration): 79 of eight_features' 243 test patients.
  Same patients, same order, same events in every case — so all 11 models are now scored
  against ONE canonical set of patient-level outcomes, taking only risk scores and native
  survival curves from each model.

Gap 5b — native survival probabilities vs. the fitted conversion.
  Every reported IBS previously came from calibrated_survival_probs(), i.e. the model's
  risk scores pushed through a Breslow baseline fitted from its own training scores. Each
  fitted estimator was inspected (not assumed score-only, per the gap):
    - GBSA            GradientBoostingSurvivalAnalysis, loss='coxph' → predict_survival_function  NATIVE
    - Survival RF     RandomSurvivalForest                          → predict_survival_function  NATIVE
    - Weibull AFT     WeibullAFTFitter                              → predict_survival_function  NATIVE
    - Cox             CoxTimeVaryingFitter — no predict_survival_function, but it does carry
                      baseline_cumulative_hazard_ (197 rows, 1e-5 … 3883.7 d), so
                      S(t|x) = exp(-H0(t)·partial_hazard) is available from the fit itself.
                      Covariates are held at the patient's landmark row (the row the model is
                      scored on); that carry-forward is an assumption of the reading, not of
                      the fit, and is labelled as such.                                        NATIVE
    - Survival SVM    FastSurvivalSVM — pure ranking model, no survival function of any kind.
                      Retains the fitted conversion, explicitly labelled.                      CONVERSION
    - DeepSurv        nn.Module trained on Cox partial likelihood, no baseline stored.
                      Retains the fitted conversion, explicitly labelled.                      CONVERSION
    - KFRE            Native at exactly 2 y and 5 y (the only horizons its published S0
                      constants define) and nowhere else, so it cannot supply a curve to
                      integrate. Its IBS stays conversion-based and labelled, and a POINT
                      Brier score at 730 d and 1825 d is now reported instead — computed for
                      every model with native output there, so KFRE's numbers have something
                      comparable beside them.                                    POINT-NATIVE
    - DDH / Hazard Transformer / Logistic Hazard / RNN-Surv already supplied native_prob_fn;
      the IBS path simply ignored it. It no longer does.
  Result: 8 of 11 models in four_features now report a native IBS. Every Brier number in the
  report carries its source, and where a native number exists the fitted-conversion number
  for the same model and window is printed next to it for contrast.

Gap 5c — treat-all decision curve.
  Was computed from raw df_test rows. Now computed from the same patient-level terminal
  outcomes, horizon and included patients as the model curves. The row-level curve is still
  printed, labelled "superseded", so the size of the correction is on the record.

Gap 5d — eGFR referral comparator.
  Two separate defects, both fixed.
  (a) Unit. Was one "decision" per eGFR ROW. Now one decision per patient: their most recent
  genuinely measured eGFR at or before their prediction landmark, carrying their terminal
  outcome. Coverage is reported explicitly (rep99: 345/345, 243/243 and 20/20 patients have a
  usable eGFR; twenty_features selects those 20 decisions from 502 measured-eGFR rows out of
  9115).
  (b) Threshold. Was ONE number per cutoff, computed at the rule's own referral fraction
  (n_high/n) used as a stand-in "implied threshold" — a value no model was being compared at,
  and one that moved with cohort composition independently of the rule's performance. An
  eGFR<cutoff rule is a fixed binary test: its TP/FP rates do not vary with the risk threshold
  pt, but its net benefit does, because pt sets the exchange rate between them. It now returns
  NB(pt) = TPrate - FPrate * pt/(1-pt) across the same DCA_THRESHOLDS as every model curve, and
  is plotted as a line on the same axis instead of a point floating at x=0.1. Section 4 below
  gives the resulting curves.

Gap 3 — uncertainty quantification.
  1000 patient-level bootstrap resamples, 95% percentile intervals for C-index, IBS and mean
  time-dependent AUC, plus paired differences against KFRE and against the best model on the
  SAME resamples (pkgs/data_analysis/bootstrap_ci.py). Predictions are computed once and
  re-indexed; measured cost 8 ms per resample per model, ≈1.5 min for 1000 × 11.
  Only test patients are resampled; the training censoring reference is held fixed.

================================================================================
2. A SIDE EFFECT WORTH RECORDING: THE TIME-DEPENDENT AUC WAS NEVER COMPUTABLE
================================================================================
Before this rework, `auc` was None for EVERY model in EVERY scenario, with the recorded
reason "censoring survival function is zero at one or more time points". That was not a
property of the data. The Brier path administratively censored test patients followed past
the training set's covered range; the AUC path did not, so sksurv always saw test follow-up
beyond the support of G(t) estimated from y_train (four_features rep99: test max 4333 d
against a training censoring distribution that runs out at 4060 d) and refused the whole
call. Applying the same cap in the AUC branch (evaluation_time_cap + _administratively_censor)
makes it compute. All 11 models now report a mean time-dependent AUC.

The superseded treat-all curve is negative across most of the threshold range; the corrected
one is strongly positive at clinically relevant thresholds. Any clinical-utility claim resting on a
model's decision curve sitting above treat-all must be re-derived against the corrected
comparator before it is repeated. Correcting the unit does not establish that any model beats
treat-all — on this mini-experiment split it mostly indicates the opposite — and the
20-patient twenty-feature split cannot settle the question either way.

================================================================================
5. WHAT THIS DOES NOT ESTABLISH
================================================================================
- rep99 is the 20-500 patient mini-experiment split. It verifies that the corrected code
  runs, produces the intended quantities, and changes the numbers in the direction and
  magnitude expected. It is not evidence about model performance.
- The paired-difference intervals are 95% percentile intervals on differences, not
  multiplicity-controlled tests across 11 models.
- Production reps 1-5 currently hold data CSVs but no trained model artifacts, so none of
  this has been run at full scale. That is the blocking dependency for the reported tables.
