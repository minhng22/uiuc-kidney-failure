1. ROOT CAUSE
--------------------------------------------------------------------------------
pkgs/experiments/cox.py:51 (pre-fix) called

    model.fit(data_train, event_col='has_esrd', id_col='subject_id')

without naming covariates. lifelines' CoxTimeVaryingFitter consumes
subject_id / start / stop / has_esrd via its own id_col/start_col/stop_col/
event_col arguments and treats EVERY remaining column of the frame as a
covariate. Two non-features therefore entered the design matrix:

  a) duration_in_days — the outcome time itself.
  b) an unnamed CSV row-index column ("Unnamed: 0"), introduced because
     pkgs/data_analysis/model_data_store.py:205 writes the cached split with
     `data_train.to_csv(train_path)` (no index=False), and line 209 reads it
     back with a plain `pd.read_csv`.

Confirmed by loading the fitted rep1 artifacts (params_.index):

  four_features                  6 covariates:
      ['Unnamed: 0', 'duration_in_days', 'age', 'gender', 'egfr', 'uacr']
  eight_features                10 covariates: ['Unnamed: 0', 'duration_in_days', ...]
  twenty_features_heterogeneous 42 covariates: ['Unnamed: 0', 'duration_in_days', ...]

duration_in_days coefficients (all positive):

  Scenario                        coef            p
  four_features                   +5.115072e-05   1.961e-11
  eight_features                  +1.259937e-04   4.289e-06
  twenty_features_heterogeneous   +1.577538e-05   1.734e-282

"Unnamed: 0" coefficients: -1.795e-07 (p=0.865), -3.160e-06 (p=0.771),
-8.933e-10 (p=7.3e-06).

Because the coefficient on duration_in_days is positive, predicted hazard
rises with duration; run_cox_model() then scores that prediction against
duration_in_days itself via concordance_index(). The result was a
systematically INVERTED ranking rather than a spuriously good one — rep1
four_features scored C-Index 0.308, and 1 - 0.308 = 0.692, essentially the
0.699 obtained after the fix.

Why Cox-specific: all ten other models select features explicitly through
pkgs/experiments/utils.py:get_tv_rnn_model_features(). cox.py was the only
module that never imported it (verified by grep across pkgs/). The analysis
layer was already immune — feature_importance_analysis.py:311-312 filters
non-features and any "Unnamed*" column.

2. FIX
--------------------------------------------------------------------------------
pkgs/experiments/cox.py:
  - imports get_tv_rnn_model_features (the same per-scenario feature table
    the other ten models use).
  - adds COX_NON_COVARIATE_COLS + get_cox_covariates(scenario, df), which
    returns that scenario's explicit feature list. It falls back to column
    exclusion (mirroring feature_importance_analysis.py's rule) only for
    HETEROGENEOUS_IMPUTE — the one scenario run_cox_model() accepts that
    get_tv_rnn_model_features() has no table entry for, because that frame
    is assembled at runtime in model_data_store.get_train_test_data() from
    the FIVELABMS subsets with the *_missing columns dropped after
    imputation. It asserts every named covariate is present in the frame.
  - run_cox_model() now fits on
    data_train[['subject_id','start','stop','has_esrd'] + covariates]
    and logs the covariate list it used.

No other module was changed. Evaluation is unaffected: lifelines 0.30.0's
predict_log_partial_hazard() selects the fitted covariates from the test
frame by name (self.regressors.transform_df(X)), so passing the full
data_test remains correct.

5. RELATED PRE-EXISTING ISSUES (NOT CHANGED — FOR THE OWNING SESSION)
--------------------------------------------------------------------------------
a) run_ti_cox_model() (cox.py, NON_TIME_VARIANT / CoxPHFitter) has the same
   class of bug: it calls fit(data_train, duration_col=..., event_col=...)
   with no covariate list, so subject_id and the "Unnamed: 0" row index
   enter its design matrix. duration_in_days does NOT leak there (it is
   consumed as duration_col). This is legacy, out of scope for the 4/8/20
   feature-set experiment, and was deliberately left untouched.

b) compute_time_dependent_auc() (cox.py:22-33) catches only MemoryError, so
   the known sksurv "censoring survival function is zero at one or more time
   points" ValueError propagates and aborts the caller. Observed on rep99
   four_features. C-Index and Brier are computed before that call and the
   model is saved before evaluation, so nothing above is invalidated;
   run_experiments.py isolates it per scenario/model anyway. Left unchanged
   (it alters behaviour for every rep and scenario).

c) pkgs/scripts/run_stage2_new_scenarios.py, cited in CLAUDE.md as the
   scoped-driver pattern, no longer exists. pkgs/scripts/run_experiments.py
   supersedes it: it already provides per-scenario/per-model exception
   isolation, CKD_REP handling, per-rep logging, and an explicit guard that
   refuses to run when a scenario's train/test CSVs are missing — which is
   what prevents the raw-MIMIC-extraction fallback described in CLAUDE.md.
   It was used for all runs above; no new driver was written.
