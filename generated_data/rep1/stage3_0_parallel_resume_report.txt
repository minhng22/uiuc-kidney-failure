STAGE 3.0 — CODE CHANGES + PARALLEL RESUME OF REMAINING rep1 EXPERIMENTS
================================================================================
User request (2026-08-26): (1) make get_device() pick the GPU with the most
available compute instead of a random one, (2) make the experiment runner
launch models in parallel instead of sequentially, (3) relaunch Stage 3.0 for
the models still blocked behind the in-progress dynamic_deephit run — without
touching that run.

1. get_device() change
-----------------------
File: pkgs/experiments/utils.py

Was: `random.randint(1, 7)` — picked a uniformly random GPU (excluding GPU 0),
regardless of load.

Now: on every call, shells out to
`nvidia-smi --query-gpu=index,utilization.gpu,memory.used,memory.total
--format=csv,noheader,nounits`, excludes GPU 0 (matching the prior behavior),
and picks the GPU with the lowest utilization.gpu%, tie-broken by most free
memory. Falls back to the old random-GPU-1-7 behavior if nvidia-smi is
missing/unparseable, and to CPU if CUDA isn't available at all. No caching —
each call re-queries live state, so concurrent processes each get a
reasonably load-balanced (though not lock-coordinated) pick.

Verified standalone before use:
  PYTHONPATH=. python3 -c "from pkgs.experiments.utils import get_device; get_device()"
  -> "Using GPU: cuda:5 (utilization=0%, free_mem=11260MiB)" — correctly
     skipped GPU 2, which had residual memory/utilization from the in-progress
     dynamic_deephit run.

2. Parallel experiment launching
----------------------------------
File: pkgs/scripts/run_rep.sh

Was: a `for experiment in "${EXPERIMENTS[@]}"` loop running each experiment's
`python -m pkgs.experiments.<name>` sequentially, all appending to one shared
LOG_FILE.

Now: each experiment is launched as its own background subshell (`&`),
each writing to its own per-experiment log
(`eval_rep<N>[_<RUN_TAG>]_<experiment>.log`) to avoid interleaved output,
then the script `wait`s on all of them and aggregates pass/fail into the
main LOG_FILE. Two new optional env vars:
  - `EXCLUDE_EXPERIMENTS` — space-separated experiment names to skip this
    invocation (e.g. `EXCLUDE_EXPERIMENTS="dynamic_deephit"`).
  - `RUN_TAG` — suffix appended to this invocation's LOG_FILE/MASTER_LOG/
    PID_FILE names (e.g. `RUN_TAG=resume_no_ddh`), so a second invocation for
    a rep that already has a live process doesn't clobber its log/pid files.
Verified with `bash -n` (syntax check) before use; correctness verified live
by the resume launch below (dynamic_deephit correctly skipped, the other 4
correctly launched as separate parallel PIDs, kfre — CPU-only, no GPU/torch
use — completed within seconds as expected).
